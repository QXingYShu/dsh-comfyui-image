Stop emitting a scalar `required` on tool schema properties

`compileProperty` stamped `required: true` onto each required property node in
addition to listing the name in the containing object's `required` array. The
second is the only valid form: JSON Schema defines `required` as an array of
property names owned by the *containing* object, so a property node carrying a
boolean is an invalid schema, and a strict gateway that validates the tool list
it is handed rejects the whole list -- costing the session every tool, not just
this one.

Validation had been reading that invalid flag back to detect a missing required
argument, so removing it is only safe together with the re-plumbing now in
`validateValue`: absent-property detection reads the owning object's `required`
array, threaded down as `requiredNames`, and `leafKey` recovers the property name
from a path so nested and array-indexed paths still report the right key.

`define-tool.mjs` asserts the schema shape rather than just the behaviour --
no reachable property node may carry a non-array `required` -- so the invalid
form cannot come back, plus coverage for nested objects, arrays and enums.
